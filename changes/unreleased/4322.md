## 2026-10-26 - Spillable compact content storage for current session state (part of #4272)

### What changed

- `packages/coding-agent/src/modes/rpc/compact-content-store.ts`: owned bounded leaves (32,768 UTF-16 code units) created synchronously in RAM. A serial asynchronous job chain spills them to a private epoch-owned spool (0700/0600). A leaf's RAM copy is released only after its file write completed; a failed write keeps the bytes resident, halts further spilling and is reported with its own retained-bytes counter. A deleted or short committed file is a typed read error, never empty content. Unreferenced files count as reclamation debt until their unlink completes, and retirement joins owned I/O before removing only its epoch directory.
- `packages/coding-agent/src/modes/rpc/compact-storage-io.ts`: the asynchronous file seam (`CompactStorageIo`, node promise filesystem default), the storage failure record and `CompactStorageReadError`.
- `packages/coding-agent/src/modes/rpc/compact-session-state.ts`: the in-memory current-state owner over that store. `accept` validates a typed transition completely, then publishes the next sequence, or throws `CompactTransitionError` with state unchanged (backwards overlap outside producer-declared coverage included). `freeze`/`read`/`release` pin and materialize immutable cuts. Settled message rows are a resident map: a status change replaces the whole row, a removal deletes it, and a transition that addresses a removed or unknown message is refused. Persistence status changes only through `message_status`, never through storage success or failure.

### Why

- senpi#4272 (contract R3.C6.4 first half, ruling 08 mechanism A): current content must be retained as current state, not as the cumulative prefixes of every update, and storage failure must keep accepted content and report it rather than drop it (R3.C2.4).

### Why an extension could not handle it

- The store and its consumer sit below extension delivery in the RPC host's session state; extensions see neither the host's retained content nor its spool directory.

### Expected merge conflict zones

- None upstream: all three files are fork-only and new.
