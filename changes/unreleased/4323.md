## 2026-10-26 - Spillable settled-row index for compact current state (part of #4272)

### What changed

- `packages/coding-agent/src/modes/rpc/compact-content-index.ts`: a keyed collection with an immutable paged disk base plus one resident override slot per key. Updates coalesce into that slot (N status updates to one row hold one slot), and a removal of a committed row is a tombstone mask until compaction folds it in. Background compaction folds only overrides whose leaves are all committed, writes copy-on-write pages, and publishes them in one synchronous swap that never removes an override newer than the one it read; a cut keeps the pages and overrides it froze. Pages are internal storage only, never a wire record.
- `packages/coding-agent/src/modes/rpc/compact-session-state.ts`: settled message rows move from the resident map to that index (`compactAboveRows`, one page by default); `storageStatus` reports override slots, deletion masks and base pages/rows.
- `packages/coding-agent/src/modes/rpc/compact-content-store.ts`, `packages/coding-agent/src/modes/rpc/compact-storage-io.ts`: page write/read operations, a committed-leaf query and a commit hook so index compaction can include rows that now reference only disk.

### Why

- senpi#4272 (contract R3.C6.4, S03 design section 4): settled row headers must be able to leave RAM; with a paged base, a status update or removal must not need the spilled row, and a stale compaction must never erase a newer update or resurrect a removed row.

### Why an extension could not handle it

- The index is internal storage of the RPC host's current-state owner, below extension delivery.

### Expected merge conflict zones

- None upstream: all four files are fork-only.
