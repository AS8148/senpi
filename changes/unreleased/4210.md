## 2026-10-25 - Host-owned MCP presenter deployment options (#4197)

### What changed

- `main.ts`: pass the deployment switch to the RPC host and interactive terminal, and the reserved bootstrap descriptor to the host without copying the descriptor into session-worker runtime configuration.

### Why

- Presenter enrollment belongs to the launch owner, not a project setting, ordinary RPC role, or worker launch specification.

### Key decisions

- Enforcement is explicitly enabled with `--mcp-presenter-enforcement`. Without it, existing RPC and terminal MCP UI behavior remains unchanged.

### Why an extension could not handle it

- The entry point owns process descriptors and the configuration handed to workers.

### Expected merge conflict zones

- LOW: RPC-host construction in `main.ts`.

## 2026-10-25 - Private presenter bootstrap launch options (#4197)

### What changed

- `args.ts`, `host-command-args.ts`, and `host-command.ts`: accept the reserved presenter descriptor and carry its live stream through the host launch API.

### Why

- An inherited private channel, not an advertised UI capability or a serialized launch argument containing credentials, establishes the launch principal.

### Key decisions

- Descriptor 4 is reserved for presenter bootstrap. Descriptor 3 remains the owner-lifetime channel. No key, challenge, or grant is put in an environment variable or command-line argument.
- An `ensure` call that reuses an existing host does not enroll its caller.

### Why an extension could not handle it

- Extensions run after launch and cannot establish an inherited launch-owner trust boundary.

### Expected merge conflict zones

- LOW: CLI option parsing and the host-command runner call.

## 2026-10-25 - Private MCP form scope and outcome contracts (#4197)

### What changed

- `mcp-form-types.ts`: define private form scopes, host-originated outcomes, whole-form requests, and host-installed private bindings.
- `mcp-mrtr-presentations.ts`: carry the private binding, actual-presentation callback, and final human-admission callback on the host-issued presenter entry.

### Why

- A cancellation result alone does not prove that a human acted. Worker and in-process paths need the same explicit settlement provenance.

### Key decisions

- Private bindings ride the same host-issued presenter entry that the runner wrapper aliases. Nothing derives or re-registers authority from the wrapped extension UI, and the binding never becomes an extension UI property, snapshot, session entry, or ordinary RPC capability.
- Operation cancellation and presentation loss remain distinct. Worker cancellation publishes an atomic fence before its asynchronous notification.

### Why an extension could not handle it

- The engine owns the binding identity and the cross-worker settlement provenance.

### Expected merge conflict zones

- LOW: the internal MRTR presentation registry; the private form contract is new.

## 2026-10-25 - Private legacy and modern MCP form routing (#4197)

### What changed

- `elicitation.ts`: route enforced legacy requests through private validation and settlement, with body-free processing failures when no presenter is available.
- `modern/request.ts` and `request-origin.ts`: retain exact operation origins, recheck private presenter readiness at attempts, and distinguish operation termination from presenter cancellation.
- `modern/consent-queue.ts`: share the existing abort-aware FIFO with the opt-in local authority while preserving the default MRTR queue.
- `modern/form-schema.ts` and `modern/elicitation.ts`: share whole-form validation and actual-presentation acknowledgement with RPC and local presenters.
- `service.ts`, `shared-connection.ts`, and `host-registry.ts`: read private authority from the session's retained host-issued presenter, propagate private origins, and separate legacy transports by initialization eligibility and enforcement policy.
- `transport-sdk.ts`: discard stderr for private-form transports rather than recording a server echo of consent data.

### Why

- A session's ordinary UI provider cannot authenticate a human or safely select an owner for an unsolicited legacy form.

### Key decisions

- Modern capability metadata remains request-scoped. Legacy capability advertisement is fixed at connection initialization, with live owner and presenter checks on each elicitation.
- A no-human request is a processing failure, explicit refusal is decline, and dismissal after actual presentation is cancel.
- Private schemas and submitted content are validated before the terminal latch; rejected submissions never admit human input.

### Why an extension could not handle it

- The MCP service owns transport initialization, request origins, shared leases, and continuation dispatch.

### Expected merge conflict zones

- MEDIUM: the stacked MRTR request executor and shared elicitation validator.
- LOW: service connection creation and stderr classification.

## 2026-10-25 - Local terminal forms use private final settlement (#4197)

### What changed

- `mcp-local-presenter.ts`: register the terminal internally, queue whole forms within their original deadlines, and route review through the host terminal latch. Collector failure terminates only that form.
- `interactive-mode.ts`: register the local private binding only with enforcement enabled, bound to the actual terminal lifetime, and avoid per-field human admission for ephemeral form primitives.

### Why

- Editing one field is not approval of the complete form. A remote attachment must not acquire the terminal's authority.

### Key decisions

- Actual rendering acknowledges presentation; final accept, decline, or explicit cancel admits once. Timeout, replacement, and disposal never fabricate human activity.
- Default terminals keep the base MRTR queue, legacy origin rules, and legacy stderr handling.

### Why an extension could not handle it

- The terminal host owns modal rendering, the actual input callbacks, and presentation disposal.

### Expected merge conflict zones

- LOW: extension UI context construction and private selector rendering.

## 2026-10-25 - Host-issued presenter grants and private form settlement (#4197)

### What changed

- `mcp-presenter-authority.ts` and `mcp-form-dialog.ts`: bind one holder to host, session, attachment, connection, principal, and presentation epochs; settle each form through one synchronous terminal latch.
- `mcp-presenter-control.ts` and `mcp-presenter-bootstrap.ts`: authenticate the launch owner with Ed25519 challenges, scope each management proof, and carry enrollment on a separate private channel. Invalid descriptors return no presenter.
- Host CLI, supervisor, and successor launch paths preserve the reserved channel without repurposing owner-watch or internal-key channels. Deferred handover relays a fresh challenge to the existing authenticated launch owner rather than copying live grants.
- `session-event-writer.ts`, `session-binding.ts`, and `connection-handler.ts`: intercept dedicated private records before ordinary queues, snapshots, replay, and extension-response admission. Accepted private writes are not dropped while a prior socket drain is pending.
- `mcp-form-worker.ts`, `session-worker-protocol.ts`, `session-worker.ts`, and `session-worker-client.ts`: carry private typed outcomes and atomic cancellation fences without using public worker output.
- `host-capabilities.ts`, `session-router-routing.ts`, and `multi-session-host.ts`: advertise presenter protocol support only with enforcement enabled, and keep ordinary host operation available if bootstrap setup fails.
- `host-lifecycle-launch.ts`: contain bootstrap import and relay failures without ending the shared supervisor or its lifetime channel; preserve the supervisor's fixed startup import budget.
- `docs/rpc.md`: document the separate bootstrap and management channels, private form envelopes, and settlement rules.

### Why

- Any attachment could previously answer a general extension form. Declared roles and capabilities are not authentication.

### Key decisions

- Unknown and stolen-dialog submissions from a non-holder receive the same authorization error before private entry lookup.
- Revoke authority before cleanup, but retain host entry references so internal timeout, detach, and replacement paths can always settle.
- Private writes bypass queue-error previews. No pending form, schema, token, draft, response, or presentation marker is part of public session state.
- Shell-based custom launch wrappers do not receive presenter authority; their ordinary RPC operation remains available.

### Why an extension could not handle it

- Only the host owns connection epochs, inherited descriptors, private output destinations, and worker termination.

### Expected merge conflict zones

- MEDIUM: host launch, handover, and session-worker protocol changes.
- LOW: private routing before ordinary command admission and UI rebinding.
